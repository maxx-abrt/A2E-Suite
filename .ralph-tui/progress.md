## Codebase Patterns (Study These First)

- **a2e-* app manifest tests** live in `src/lib/__tests__/*.test.ts`, run with `node --test --experimental-strip-types`. Import each declarable module and `assert.equal(module.default.success, true)` before reading `module.default.config`; view/page-layout/widget/nav/role configs all come back on `config`. Native standard field ids for views resolve via `STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS[object].fields[name].universalIdentifier` — do not import twenty-shared into the standalone app.
- **a2e-* quality gates**: `yarn test:unit` + `yarn typecheck` + `yarn lint` + `npx twenty dev:build .`. `npx nx lint:diff-with-main <app>` reports "Cannot find project" (apps are not Nx projects); format `src/lib/**` with a lib-inclusive oxfmt config because the root `.oxfmtrc.jsonc` ignores `**/lib/**`. Uncommitted server edits are invisible to `npx nx lint:diff-with-main twenty-server` ("No changed files" — it diffs `main...HEAD`), so run `npx oxlint --type-aware -c .oxlintrc.json <globs>` + `npx oxfmt --check <globs>` directly; use globs, not a `$(find …)` variable — zsh does not word-split it, so a joined path lints as one file and shows a false green.
- **a2e-chat P5.1 chat-model contract**: native chat is app-owned metadata, not a server table. Five `c31c*` objects (`chatChannel` w/ kind WORKSPACE/PROJECT/CUSTOM + visibility PUBLIC/PRIVATE + postingRoles MULTI_SELECT, `chatChannelMember` junction, `chatMessage` w/ channel/author/threadParent self-relation, `chatReaction`, `chatReadCursor`) get channel/member/reaction/readCursor CRUD auto-generated by the metadata engine; the `src/modules/chat/` domain module only adds what metadata cannot — a newest-first keyset `chatMessages` connection over one channel (cursor = base64url `{createdAt,id}` so same-ms messages never collide; WHERE is `channelId` only, never `workspaceId`, because tables are per-workspace schemas) and an ephemeral `sendChatTypingIndicator` mutation. Register the module in `CoreEngineModule.imports` and decorate the resolver `@MetadataResolver()`. Typing fans out on `workspace:<id>:chat:<channelId>` (parser already accepts `chat`); do not fork the email `messaging` module.
- **a2e-documents content-template reuse (P1.6e)**: a content template is a `_document` record with `kind: 'TEMPLATE'`; instantiation is a pure payload (`buildTemplateCopyPayload` → a fresh `DOCUMENT` record) that re-keys every blocknote block id while deliberately preserving `threadId`, and excludes relations/system fields (`id`/`parentId`/`companyId`/`personId`/`archivedAt`/`isFavorite`). Delete-safety is structural — a copy carries no template id/FK, so deleting the template cannot cascade; editing a copy cannot mutate the template (asserted in the 107-case lib suite). The app declares no attachment field on documents, so permission-aware attachment/ID remapping is N/A here (it belongs to app objects that do carry attachments). "Edit template" is a product call: editing = the TEMPLATE record's own page (banner says copies are unaffected) — do not build a second editor. Tier-0 gates: `node --test src/lib/__tests__/*.test.ts`, `npx tsc --noEmit`, `yarn lint`, `npx twenty dev:build .`.
- **a2e-projects view contract**: a KANBAN view's `mainGroupByFieldMetadataUniversalIdentifier` must be the app field id you intend (e.g. `TASK_FIELD_IDS.projectStatus`, not the native task `status`), and `groups[].fieldValue` must equal the target SELECT option *values*. Project-scope a task view with `ViewFilterOperand.IS_NOT_EMPTY` + `value: ''` on the relation field. Existing views can pass the manifest graph-walk yet group by the wrong field — assert the semantic target in a focused unit test, don't rely on reference-resolution alone.
- **a2e-projects calendar view contract**: a `ViewType.CALENDAR` view places records by `calendarFieldMetadataUniversalIdentifier` (must be the intended date field, e.g. native task `dueAt`) with `calendarLayout` (`ViewCalendarLayout.MONTH`); it renders on the native record-calendar grid and only displays — declaring one creates no provider event/invitation (P4C.5 owns sync). The existing graph walk resolves the calendar field but cannot catch a missing project scope: assert `calendarFieldMetadataUniversalIdentifier === dueAt` and the `IS_NOT_EMPTY` project filter explicitly. Task-view filter uids continue `c31b0100-0005-…`.
- **a2e-projects smart-list / nav-folder contract**: a multi-list "page" is a `NavigationMenuItemType.FOLDER` nav item (one entry, reserved position) whose children are `VIEW` nav items carrying `folderUniversalIdentifier` — there is no primitive that composes several views otherwise. "Current user" filters all share the value `JSON.stringify({ isCurrentWorkspaceMemberSelected: true, selectedRecordIds: [] })`; a native relation (`assignee`) filters directly on the field, while an ACTOR system field (`createdBy`) also needs `subFieldName: 'workspaceMemberId'`. Derived system-field ids come from `STANDARD_OBJECT_UNIVERSAL_IDENTIFIERS.task.fields.createdBy.universalIdentifier` (do not hardcode). "Overdue" = `dueAt` `ViewFilterOperand.IS_IN_PAST` with `value: ''` AND native `status` `IS_NOT` `'DONE'` (keep select-status, no custom-status object). Nav/view/filter/sort uids continue their existing families (`c31b0000-0010-…`, `c31b0100-0003-…`, `c31b0100-0005-…`, `c31b0100-0006-…`).
- **a2e-projects page-layout tab contract**: a record page tab hosts widgets; a table or kanban list is a `type: 'RECORD_TABLE'` widget with `objectUniversalIdentifier` (the view's object) + `configuration: { configurationType: 'RECORD_TABLE', viewUniversalIdentifier: <view uid> }` — the renderer (`RecordTableWidgetRenderer`) reads the referenced view's layout, so a plain TABLE view renders a table and a plain KANBAN view renders a kanban with no extra component (`WidgetType.VIEW` is rejected server-side). Native relation-scoped tabs are `type: 'FILES' | 'TASKS' | 'NOTES'` with only `configuration: { configurationType }` (no object/view needed; they read the record's morph inverse, e.g. `attachments`). Widget `viewId` becomes `viewUniversalIdentifier` in the manifest and resolves back to `viewId` on install. Uids continue the tab `c31b0200-0009-…` / widget `c31b0200-000a-…` families. App objects auto-provision the `attachments`/`timelineActivities`/`noteTargets`/`taskTargets` morph inverses, so a `FILES` widget and a `timelineActivities` Core query both resolve on the project object.
- **P6 Drive folder modeling (decided, report-only)**: model folders as a `driveFolder` app object (`name`, `parent` self-relation tree, color/icon, `position`) plus an **additive** `folderId` MANY_TO_ONE relation on the standard `attachment` object (inverse `files`, `SET_NULL`) — **not** a new target on the `attachment` `targetMorphId` morph set. The morph set means "record this file is attached to"; folder is an orthogonal, view-filterable organizational axis that coexists with a morph target. `folderId`/`sourceApp`/`starred` are organization/attribution, never permission (C5). Caveat: `folderId` only organizes `attachment` records — files stored in arbitrary FILES fields / rich-text bodies are `FileEntity` rows, not attachment records; project over both, don't build a second file system. Standard `attachment` extension has no in-tree precedent (existing app fields target person/task/company/opportunity), so confirm `dev:build`+install when implementing P6.1 bullets 2–3.
- **twenty-server unit-test async pattern**: `packages/twenty-server/jest.config.mjs` sets `fakeTimers.enableGlobally: true`, so `setImmediate`/`setTimeout` never fire inside specs — a test that must flush an async continuation started by an event handler (e.g. `handleConnection` → `message` → subscribe promise chain) flushes microtasks with a small `await Promise.resolve()` loop, not `setImmediate`. Private gateway handlers are reachable from tests via the public `handleConnection(fakeSocket, request)` seam plus `EventEmitter` sockets (`readyState = 1` so `send` is exercised).
- **onboarding install-apps auto-skip guard**: the native `InstallApps` step auto-skips (`InstallAppsAutoSkipEffect`) when the marketplace catalogue yields 0 available apps. The A2E build hosts the workspace-template picker on that same step, so auto-skipping an empty catalogue silently discards the template choice. Gate the decision with the pure `shouldAutoSkipInstallAppsStep` util (`hasTemplateChoices` holds it open whenever a picker is rendered); keep the picker passed or the discard returns. Front util tests live at `src/modules/onboarding/utils/__tests__/*.test.ts` importing via the `@/` alias.
- **blocknote version-history restore pattern**: `EditorVersionHistoryStore.addRestoreSnapshots({ currentBody, restoredBody })` is the durable "restore as new revision" seam — it delegates to `addSnapshot` for both bodies (one fire-after-emit persistence/prune path), so restoring appends the left state and the restored body instead of waiting for `useEditorVersionHistory`'s 120s interval snapshot; the panel must call it before `editor.replaceBlocks`. Never write the server directly or fork a second history store.
- **P1.6d persona bundle preview contract**: a persona's proposed starter contents live in `WORKSPACE_TEMPLATE_DEFINITIONS[template].starterBundleContents` as `{ applicationUniversalIdentifier, label, locale }` items and are preview-only — `getWorkspaceTemplatePreview` maps them into `TemplatePreview.samples`, filtered to apps that are `registered && versionCompatible` (the "only compatible ready apps" rule; CRM has none). The seeding source of truth stays each app's post-install starter payloads (`starter-templates.ts`/`starter-projects.ts`/`starter-books.ts`); never derive writes from the server constant. Adding contents does NOT require a `version` bump (applies are unchanged); changing the app set does, and cascades into the `version: 1` assertions in `workspace-template.service.spec.ts`, the fixtures, and the two onboarding integration specs. No preset currently installs a2e-projects (`4f759655-84f8-434d-9c76-ee1850e8c1a4`), so adding the project/retroplanning bundle to a persona is an app-set change, not a content change.
- **twenty-server app upgrade/lifecycle test harness (P1.7a)**: exercise install→upgrade through the tarball path — `createAppTarball({'manifest.json': JSON.stringify(buildBaseManifest({appId, roleId, overrides})), 'package.json': JSON.stringify({name, version})})` → `uploadAppTarball` → `installApplication({input:{universalIdentifier}})`; `installApplication` on an already-INSTALLED app performs the upgrade and `uploadAppTarball` of a higher version re-registers `latestAvailableVersion`. A failed upgrade (proven with the cross-entity universalIdentifier conflict the native validation suite uses) commits `application.version` from the incoming package BEFORE `syncMetadataFromManifest` validates, so the row rolls `state` back to INSTALLED while still advertising the unapplied version — the rollback must restore `previousVersion` too. Owned-object rows are written with raw SQL (`INSERT INTO "<schema>"."_<nameSingular>" ("id","name","createdByName","updatedByName")`) against the run-unique table name; delete the rows before cleanup or the C3 data-loss preflight refuses the uninstall and orphans metadata.
- **a2e-inbox P8.1 notification-service contract**: one core-schema `notification` table (`NotificationEntity extends WorkspaceRelatedEntity`, columns `userId`/`type`/`payload` jsonb/`readAt`/`archivedAt`) backed by a `2-39` fast instance command and registered in `instance-commands.constant.ts` + `CoreEngineModule.imports`. Producers never write rows — they inject `NotificationService.requestNotifications`, which emits the custom `notification_requested` batch event; `NotificationRequestedListener` (`@OnCustomBatchEvent`, best-effort try/catch like the usage listener) calls `dispatchNotifications`. Per-user per-type channel prefs + quiet hours are one `USER_VARIABLE` keyValuePair row (`key: notification-preferences`, `workspaceId: null`; the partial unique index makes `set` upsert correctly) normalized on every read (unknown types/channels dropped, minutes clamped). Channel `NONE` skips, `INBOX` persists a row, `EMAIL` becomes an epoch-aligned 15-min digest batch; quiet hours suppress EMAIL candidates (returned as a count, not lost) and never touch the inbox. Raw `@InjectRepository(TEntity)` on a core entity trips `twenty/prefer-workspace-scoped-repository` — suppress with a reason like document-share.
