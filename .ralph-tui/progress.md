## Codebase Patterns (Study These First)

- **Detect Apollo permission denials with `isGraphqlErrorOfType(error, 'FORBIDDEN')`** (`twenty-front/src/utils/is-graphql-error-of-type.util.ts`). It handles Apollo v4 `CombinedGraphQLErrors` (`.errors[0].extensions`) as well as plain `{extensions}`/`{code}` shapes; do NOT read `error.graphQLErrors` directly — v4 mutation errors do not expose that property, so a manual check silently falls through to "network error".
- **Template preview/apply error vocabulary is mirrored by hand** between `twenty-server/.../onboarding/types/apply-template-operation.types.ts` and `twenty-front/.../a2e-workspace/types/apply-template-operation.types.ts`; the GraphQL DTO enum registers by MEMBER NAME (wire value == member name). The front union may add client-only codes (`NETWORK_ERROR`) that the server enum omits.
- **App-owned additive task relations follow the `parentTask`/`subtasks` shape**: add a NEW MANY_TO_ONE field on the standard task (join column, SET_NULL) + its ONE_TO_MANY inverse `defineField`, with fresh universal identifiers only. Cycle guards for these self-relations stay injected-free synchronous libs over a `Map<taskId, linkedId>` (`lib/task-tree.ts`, `lib/task-dependencies.ts`) so `node --test --experimental-strip-types` covers them without a server. Never rename/retarget a committed, installed relation (`blockIssue` is task➜note and stays that way).
- **Local calendar events are channel-less standard `calendarEvent` rows.** There is no second store: the provider-independent create path is the generic record UI, opened by `isUICreatable: true` on the object + `isUIEditable: true` on the content fields (provider-synced fields stay false), and the read filter is the pure `resolveCalendarEventVisibility` (creator = owner FULL, others REDACTED reusing the METADATA default). Existing workspaces do **not** auto-resync standard UI flags — ship a `2-39-workspace-command-…` UPDATE on `core.objectMetadata`/`core.fieldMetadata` (pattern of the 2-13 `sync-standard-ui-capability-flags` command). A calendar post-query hook splice IS honoured for `findMany` but a findOne payload mutation is not reflected in the response, so test local visibility through `findMany`.
- **Adding a member to `AppPath` (`twenty-shared`) requires rebuilding `twenty-sdk` too, not just `twenty-shared`.** `twenty-sdk/dist/front-component/index.d.ts` bundles its own `declare enum AppPath`; `twenty-front-component-renderer` types `NavigateFunction` off that bundled copy while `twenty-front` imports `AppPath` from `twenty-shared/types`. The two are nominally distinct string enums, so after any `AppPath` edit the front `tsgo` fails with `Argument of type 'AppPath.X' is not assignable to parameter of type 'AppPath'` in `useFrontComponentExecutionContext.ts`/its spec. Fix: `npx nx build twenty-sdk --skip-nx-cache` (dist is git-ignored) after `npx nx build twenty-shared`. Also note `npx nx lint:diff-with-main <pkg>` diffs `main...HEAD` and prints "No changed files." on an uncommitted slice — run `npx oxlint --type-aware -c .oxlintrc.json <files>` + `npx oxfmt --check <files>` directly. In zsh, unquoted `$FILES` is NOT word-split — use `ARR=(${(f)FILES}); cmd "${ARR[@]}"`.
- **Native custom pages (`Drive`, `Inbox`, `Discussions`, and now `Calendar`) are route-only**: register in `createWorkspaceRouteObjects` before the `*` catch-all, add the enum member, and add NO side-panel `handle` and NO nav-menu seed. The `createWorkspaceRouteObjects.test.tsx` "verified panel pages" spec asserts the exact side-panel route list, so a stray `workspaceSurfaces: MAIN_AND_SIDE_PANEL` handle breaks it; navigation menu items are workspace objects, not hardcoded paths.
- **Front lint gotchas that bite new files** (oxlint from `packages/twenty-front`): `twenty/no-state-useref` flags every `useRef` whose type argument is not `HTML…Element|Element` (including `useRef(false)` / `useRef<Array<HTMLButtonElement|null>>([])`) — the repo convention is `// oxlint-disable-next-line twenty/no-state-useref`; `twenty/max-consts-per-file` allows exactly ONE `const` declaration per file, so split constants into one-const files; and `isNonEmptyString` does NOT exist in `twenty-shared/utils` (AGENTS.md is stale) — use `value.length > 0`.
- **Timezone-safe calendar writes**: build an instant from a wall-clock slot with `Temporal.ZonedDateTime.from({ timeZone, year, month, day, hour, minute }, { disambiguation: 'compatible' })` — spring-forward gaps shift forward and fall-back folds keep the earlier offset. Keep the pure inverse (`getCalendarEventSlotFromInstant`) so edit round-trips and DST tests stay server-free. All-day events are stored as UTC-midnight instants with an exclusive next-midnight end, the convention `getCalendarEventSpan` already collapses.
- **Assistant context for a non-record surface (channel/invoice) is state-driven, not context-store-driven**: `useAiChatSuggestedPromptsContext` reports `{ browsingContextType: 'chatChannel', objectNameSingular: 'chatChannel' }` read from `selectedChatChannelIdState` (on `/discussions`) / `viewableChatChannelIdComponentState` at the current side-panel page id (on the AI chat page — reuse `getAiChatContextStoreInstanceId`'s instance), and `useContextToolButtons` then offers the app's tools through the owning-app path (the app owns the object) — no new registry/mapping. A new surface type needs a `getAiChatSuggestedPrompts` branch, or the record-page fallback wording leaks onto it. `useAtomComponentStateValue(atom, instanceId)` is safe to call from outside the provider as long as the instanceId is a non-empty string (pass `contextStoreInstanceId`).
