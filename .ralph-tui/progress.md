## Codebase Patterns (Study These First)

*Add reusable patterns discovered during development here.*

- **Registering a new internal `a2e-*` app (US-147, a2e-links):** adding a directory under `packages/twenty-apps/internal/a2e-*` trips a front drift guard (`packages/twenty-front/src/modules/a2e-workspace/constants/__tests__/A2eSuiteApplicationUniversalIdentifiers.test.ts`) that scans the real app dirs. Five edits are required and must stay in sync: (1) `A2eSuiteApplicationUniversalIdentifiers.ts` allowlist, (2) `OnboardingInstallableApps.ts` (Lingui `msg`, new strings are fine — never run `lingui extract`), (3) the server parity list `onboarding-installable-app-universal-identifiers.ts`, (4) `packages/twenty-docker/twenty/Dockerfile` (`COPY` + the `for app in …` loop), (5) the guard's hardcoded expected app-name array + its "six"/"seven" test name. The US-086 commit is the reference shape. App-level identity must be read from `src/application.config.ts` or `src/constants/universal-identifiers.ts` (`export const APPLICATION_UNIVERSAL_IDENTIFIER = '…'`).
- **App manifest `dev:build` output is gitignored:** an internal app's `.twenty/output/{manifest.json,package.json,…}` is regenerated by `npx twenty dev:build .`; never commit it. The Dockerfile builds each app with `yarn install --immutable && yarn twenty dev:build --tarball`, so a committed `yarn.lock` must be immutable-clean (`yarn install --immutable` exit 0) or the image build breaks. Orphan `.field.ts` drafts left by an interrupted run still get globbed by the SDK build — a failed session's half-written files must be deleted, not just ignored.

- **Inline-content mention block (US-144, dateReminder):** a custom inline content is registered in `blocknote-editor/blocks/Schema.ts` `inlineContentSpecs` via `createReactInlineContentSpec` (`propSchema` + `content: 'none'`, plus `toExternalHTML` so Markdown/DOCX degrades to a label instead of a missing node). Unlike block-inserting slash items, an inline-content slash entry that needs hooks (record creation, snackbar, account resolution) ships as a hook called in `BlockEditor.tsx` (`useDateReminderSlashMenuItem(editor)`) and is appended to the `slashMenuItems()` array — the hook returns a `SuggestionItem` whose `onItemClick` uses `editor.insertInlineContent([{ type, props }, ' '])`. Keep the builder (`buildDateReminderMention`) pure and locale/timeZone-injected so it is Jest-loadable (the real `@blocknote/*` dist cannot be imported under Jest).
- **Host-side Syna recipe family (no app, US-143):** prompt/action recipes ship as a host `SynaRecipeDescriptor` registry in `twenty-front/src/modules/ai/` (`TemplateDescriptor` + `status`/`requiredToolName`/`prompt fr+en`/`deferral`/source), projected to the gallery via `HOST_TEMPLATE_DESCRIPTOR_GROUPS` as a synthetic `a2e-host-syna` group containing only READY recipes. Each AI recipe names its registry tool through `buildLogicFunctionToolName` and install-gates on the owning app's universal identifier; the P7 invoice recipe stays registry-only `DEFERRED`. Apply is confirm-first (`useSynaRecipeApply` stages the prompt as a Syna draft, writes nothing). A new gallery category must be added to the shared closed `TemplateDescriptorCategory` union, then `npx nx build twenty-shared --skip-nx-cache` (and twenty-sdk) before twenty-front tsgo.
- **Provider-free block views + storybook stories (US-145):** to story an M8a block without the app provider tree, extract the block's pure render into `blocknote-editor/blocks/views/<Name>View.tsx` (no `@blocknote/*`, no Twenty metadata/apollo hooks — just props + `twenty-ui`/Lingui) and have the `createReactBlockSpec` render call it; stories import the view directly. Custom-block props that feed a `contentRef` slot (e.g. `TodoTaskView`) render a plain `title` when `contentRef` is undefined so the story shows content. Default BlockNote structural blocks (toggle/toggle heading/columnList/quote/code/divider/table) plus our `tableOfContents` are shown by one bare `useCreateBlockNote({ schema: BLOCK_SCHEMA, initialContent })` + `<BlockNoteView theme={colorScheme} editable={false} slashMenu={false} sideMenu={false} formattingToolbar={false} portalElements={{ default: null }} />` inside `ThemeProvider colorScheme applyToRoot={false}` — no app tree, and the table cell shorthand is just `cells: ['Block', 'Status']`. Stories are excluded from oxlint via `.oxlintrc.json` `ignorePatterns`, so lint them with oxfmt and rely on tsgo + `storybook:build` for type/bundle coverage.
