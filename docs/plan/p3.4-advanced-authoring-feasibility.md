# P3.4 advanced authoring — native-primitive & license feasibility

**Status:** report-only feasibility spike. No implementation. Findings are
**Observed** in source at baseline `7d0651f0` (2026-09-18); no runtime, browser
or export package was executed. This document is the gate half of the P3.4
bullet *"After a native-primitive/license feasibility check: embedded native
record views, charts, math/diagrams, multi-column authoring, text review
accept/reject, font/page-layout/export controls"* (`PLAN.md`). The advanced
blocks implementation story stays closed until (a) this check is accepted and
(b) durable save/share acceptance has landed. Guest editing is out of scope —
`PLAN.md` defers it explicitly. The broader fidelity/licensing owner decision is
**D07** (`PLAN.md`).

## Scope and method

- Read the real editor integration, not a mock: the document body is a
  `FieldType.RICH_TEXT` on `a2e-documents` and renders through the shared
  BlockNote schema `packages/twenty-front/src/modules/blocknote-editor/blocks/Schema.ts`.
- Reused primitives only: no reference package was read, imported or installed;
  no parallel JSON/database engine was proposed. `Inspiration apps/` was not used.
- Every capability below is cited by source path; "absent" means no first-party
  or installed primitive was found.
- Evidence vocabulary follows `docs/README.md`: **Observed** (source, named
  baseline), not **Verified** (no check run).

## What exists today

- **Editor:** BlockNote `0.51.4` (`@blocknote/core|react|mantine|xl-docx-exporter|xl-pdf-exporter`,
  `packages/twenty-front/package.json`). Schema = `defaultBlockSpecs` +
  custom `callout` and `file` block specs + custom `mention` inline spec
  (`blocknote-editor/blocks/{Schema,CalloutBlock,FileBlock,MentionInlineContent}.tsx`).
  So headings H1–H6, paragraph, bullet/numbered/check/toggle lists, quote, code,
  divider, table, image, video, audio, and nested child blocks are available.
- **Export menu:** three formats, `blocknote-editor/export/components/BlockEditorExportMenu.tsx`:
  - **PDF** — browser `window.print()` on the live editor DOM (adds an
    `a2e-print-editor` body class). No PDF library in this path.
  - **DOCX** — `@blocknote/xl-docx-exporter` (`exportBlocksToDocxBlob.ts`).
  - **Markdown** — BlockNote's lossy `blocksToMarkdownLossy`.
  - A second, library-based PDF path (`@blocknote/xl-pdf-exporter` +
    `@react-pdf/renderer`) exists only for the command-menu note export
    (`command-menu-item/record/single-record/utils/exportBlockNoteEditorToPdf.ts`).
  - Known degradations are surfaced to the user (`exportFidelity.ts`):
    `docx`/`markdown` → callout degrades, file omitted, mention degrades; `pdf`
    → none (prints live DOM).
- **Native record-view primitive (not an editor block):** a reusable embedded
  view renderer exists — `RecordTableWidgetRendererContent` (TABLE/KANBAN/LIST/CALENDAR)
  under `packages/twenty-front/src/modules/page-layout/widgets/record-table/`,
  already reused inside record pages by `FieldWidgetRelationTable`. Full record
  pages render through `PageLayoutRecordPageRenderer`
  (`modules/object-record/record-show/components/`). There is **no**
  `RECORD_PAGE` member in the widget-type union
  (`packages/twenty-shared/src/types/page-layout/WidgetType.ts`) and **no**
  record/embed block in the BlockNote schema. A record in a body is only the
  inline `mention` chip; `a2e-documents` emulates a record source link with a
  plain paragraph + link (`lib/record-note-copy.ts`).
- **Native charts (not an editor block):** page-layout `GRAPH` widgets —
  `GraphType` = VERTICAL_BAR / HORIZONTAL_BAR / LINE / PIE / AGGREGATE
  (`modules/side-panel/pages/page-layout/types/GraphType.ts`), rendered by
  `modules/page-layout/widgets/graph/` (Nivo `@nivo/line|pie`, custom SVG bars,
  `d3-shape`) and fed by server aggregate resolvers
  (`twenty-server/src/modules/dashboard/chart-data/`). Charts are private to
  `twenty-front`; `twenty-ui` has no chart component or chart dependency.
- **Multi-column:** `@blocknote/xl-multi-column@0.51.4` is **already installed**
  — transitively, because both XL exporters depend on it (`yarn.lock`; it
  exports `multiColumnSchema`/`withMultiColumn` adding `column`/`columnList`).
  It is not referenced by the app and not wired into `BLOCK_SCHEMA`.
- **Text review accept/reject:** absent. No `@blocknote/xl-suggestion`. What
  exists is adjacent, not per-edit review: block-level version diff +
  whole-version restore (`blocknote-editor/version-history/`), comment threads
  (`blocknote-editor/comments/`), and whole-document save-conflict keep/use
  (`RichTextFieldEditor`).
- **Font / page-layout controls:** absent for the BlockNote document editor. No
  font-family/size, page size, margins, headers/footers. The `a2e-print-editor`
  body class has **no CSS rule** anywhere (observed only at its add site). A
  separate TipTap `advanced-text-editor` has typography and columns
  (`modules/advanced-text-editor/`), but it is used for form/AI/email editing,
  not documents — reusing it would be a second editor system.

## Licensing constraints (the material finding)

| Package | Version | License |
| --- | --- | --- |
| `@blocknote/core / react / mantine` | 0.51.4 | MPL-2.0 (file-level copyleft; commercial use allowed) |
| `@blocknote/xl-docx-exporter` | 0.51.4 | **GPL-3.0 OR PROPRIETARY** |
| `@blocknote/xl-pdf-exporter` | 0.51.4 | **GPL-3.0 OR PROPRIETARY** |
| `@blocknote/xl-multi-column` (transitive) | 0.51.4 | **GPL-3.0 OR PROPRIETARY** |
| `@blocknote/xl-math` | not installed | (would be GPL-3.0 OR PROPRIETARY) |
| Nivo, `@react-pdf/renderer`, `katex`, `docx` | — | MIT |
| `d3-shape` | — | ISC |

- The repository is **AGPL-3.0** at the root (`LICENSE`, `package.json`), and
  `twenty-front` is not in the MIT sub-package list. GPL-3.0 libraries can be
  combined into an AGPL-3.0 work, so the *current* open-source posture is
  compatible — but the `xl-*` packages are **dual GPL-3.0 / proprietary**, and
  every closed-source or otherwise GPL-incompatible distribution would require a
  paid BlockNote commercial license. `twenty-front` already imports
  `xl-docx-exporter` and `xl-pdf-exporter`, so this decision predates P3.4 and is
  not introduced by it.
- Consequence: **multi-column and math add no new license class** (multi-column
  is already present transitively; math would join the same dual-license set),
  but they do deepen the GPL-3.0 dependency and therefore belong to **D07**, not
  to an executor's unilateral choice.
- No license policy file exists in the repo (`LICENSE-POLICY`/`NOTICE`/`THIRD_PARTY`
  absent); D07 should record the AGPL-vs-commercial position explicitly.

## Fidelity requirement and ODT

- **PDF/DOCX fidelity is required** by `PLAN.md`. Today that is only partially
  met: PDF prints the live DOM (so every rendered block survives at print
  time), while **DOCX and Markdown explicitly degrade** the custom blocks
  (`callout` degrades, `file` omitted, `mention` degrades) — the user sees the
  warnings but the result is not faithful. Any advanced block must either
  round-trip into DOCX/PDF or be declared unsupported with an explicit warning;
  "silently accepted" is forbidden.
- **ODT export remains deferred.** No `@blocknote/xl-odt-exporter` is installed
  (only the unintegrated reference app declares one). This review does not
  change that; ODT stays deferred pending the D07 decision.
- "Round-trip save/reload/export" is a per-block acceptance bar: a supported
  block must survive save → reload → export, and anything short of that stays
  explicitly deferred.

## Recommendation and sequencing

1. **Keep the advanced-authoring implementation bullet closed.** This spike is
   evidence, not a go-ahead to ship. Durable save/share acceptance (P3.2/P3.3)
   must land first.
2. **Escalate the licensing position to D07.** `twenty-front` already ships
   GPL-3.0/proprietary BlockNote XL packages; the owner must ratify the
   AGPL-3.0 reading (or buy a commercial license) before any further XL
   dependency is added.
3. **If staged later, order by risk:** multi-column (already installed, native
   round-trip) → charts / record-view embeds (reuse first-party primitives,
   behind advanced controls, with an explicit export-degradation contract) →
   math (only after D07, KaTeX-first-party fallback) → text review and
   font/page-layout (no native primitive today; separate decisions).
4. **Never** import a reference package or invent a JSON database engine; the
   reusable primitives above already exist.

## Explicitly not done (by design)

- No schema, package, server or editor change.
- No package install/uninstall; no `Inspiration apps/` read.
- No runtime/browser/export execution — Tier 0 source observation only.
- Guest editing (deferred by `PLAN.md`) and D07's mobile/music scope are out of
  this spike.
